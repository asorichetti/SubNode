# SubNode Architecture

## System Overview

SubNode is a self-hosted, invite-only community platform. Each deployment is an isolated instance—there's no central server connecting different instances.

## Core Concepts

### Node (SubNode)
A "node" is a community/cluster, similar to a subreddit or a Lobsters tag group. Each node has:
- Name and description
- Moderators
- Rules
- Associated tags

### Post
A submission to a node:
- Title
- Body (markdown supported)
- URL (optional, for link posts)
- Upvotes/downvotes
- Timestamp
- Author

### Comment
Nested threaded comments on posts:
- Parent-child relationship
- Upvotes/downvotes
- Markdown supported

### User
Authenticated users with:
- Username
- Role (admin, moderator, member)
- Join date
- Invite code they joined with (if applicable)

### Invite Code
The gatekeeper mechanism:
- Generated by admins/moderators
- Single-use or multi-use
- Expirable
- Tied to a specific role (member/moderator)

## API Design

### Auth Endpoints
```
POST   /api/auth/register          # Register with invite code
POST   /api/auth/login             # Login
POST   /api/auth/logout            # Logout
GET    /api/auth/me                # Current user
```

### Invite Endpoints (Admin/Mod only)
```
POST   /api/invites                # Create invite code
GET    /api/invites                # List invite codes
DELETE /api/invites/:id            # Revoke invite code
```

### Node Endpoints
```
GET    /api/nodes                  # List all nodes
GET    /api/nodes/:slug            # Get node details
POST   /api/nodes                  # Create node (admin)
PATCH  /api/nodes/:slug            # Update node
DELETE /api/nodes/:slug            # Delete node (admin)
```

### Post Endpoints
```
GET    /api/nodes/:slug/posts      # List posts in node
GET    /api/posts/:id              # Get post details
POST   /api/nodes/:slug/posts      # Create post
PATCH  /api/posts/:id              # Update post
DELETE /api/posts/:id              # Delete post
POST   /api/posts/:id/vote         # Vote on post
```

### Comment Endpoints
```
GET    /api/posts/:id/comments     # List comments
POST   /api/posts/:id/comments     # Create comment
PATCH  /api/comments/:id           # Update comment
DELETE /api/comments/:id           # Delete comment
POST   /api/comments/:id/vote      # Vote on comment
```

### Search
```
GET    /api/search?q=...           # Search posts and nodes
GET    /api/tags/:name             # Filter by tag
```

## Security Model

1. **Invite-only registration**: No public signup without valid invite code
2. **JWT auth**: Stateless authentication via JWT tokens
3. **RBAC**: Three roles—admin, moderator, member
4. **CORS**: Configurable per deployment
5. **Rate limiting**: Prevent abuse on public endpoints

## Deployment

### Minimal (Single Pod)
- Frontend + Backend + SQLite in one container
- For personal/single-user instances

### Standard (Recommended)
- Frontend (Nginx/React)
- Backend (Go API)
- PostgreSQL
- Redis (optional, for caching)
- All in separate pods

### Helm Chart
Provides configurable deployment:
- Resource limits
- Ingress configuration
- Database credentials
- SSL/TLS support
